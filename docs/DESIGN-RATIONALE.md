# Design rationale

Every row cites the file:line of the current repository where the choice is stated or implemented.

| Choice | Why | Where (file:line) |
|---|---|---|
| Analytical model: `K`-token fluid window, per-source rate `λ_s`, token cost `k_s`, per-event separability `d_s² = 2·KL` | Gives a closed form for the window's separability `Δ²` that is falsifiable cell by cell, instead of a black-box AUC number with no mechanism | `docs/THEORY.md:21-33` (notation) |
| Saturation condition `T·Σλk ≥ K` splits the model into two regimes (Proposition 1 vs. Corollary 3) | The two regimes have different closed forms (`h = K/Σλk` vs. `h = T`); collapsing them would hide the sign flip that Corollary 3 documents | `docs/THEORY.md:63-72` (Prop. 1), `docs/THEORY.md:154-168` (Cor. 3) |
| Admission threshold `θ = φ′_S/(1-φ′_S)` as the pass/fail rule for adding a source | Reduces the addition decision to one inequality (`ρ_S ≥ θ·ρ̄`) that a simulation can test by sign, not by fitting a curve | `docs/THEORY.md:81-97` (Cor. 1) |
| Corollary 4 treats tokenization/fusion as a lever on `k_s`, not a separate model | One closed form (`Δ² ∝ 1/k`) explains both "cheaper tokenizer helps" and "naive fusion can flip the Corollary 1 sign" without adding parameters | `docs/THEORY.md:169-192` |
| Corollary 5 optimal allocation solved by ratio ordering (continuous knapsack), stated as a ceiling, not an achievable target | Keeps the claim honest: the simulated recency/random/optimal policies are compared against an upper bound, not against each other pretending the ceiling is reachable | `docs/THEORY.md:193-213` |
| Displacement replication (`01-displacement-replication.md`) uses `N = 200,000` users/cell, 5 seeds, over 720 cells | `N` and seed count were set so the empirical AUC standard error stays below the pre-registered acceptance band `max(0.005, 3·SE)`; the sealed run confirms this — e.g. cell `i_celula=30` has `ep = 0.000348` (`3·SE ≈ 0.00105 < 0.005`), well inside the threshold, so `N=200,000`/5 seeds was not over- or under-powered for that band | `data/prereg/01-displacement-replication.md:80,93,108,141-142,150`; measured SE in `output/figures/fig3_values.json` (`painel_a.pontos[0].ep = 0.00034849125309541635`, `limiar_teste: 0.005`) |
| Token-KAT addendum uses `N = 100,000` per (cell, combo, seed), smaller than the displacement replication's `N = 200,000` | Lower `N` was budgeted because the token-KAT grid runs 8 cells × 2 combos × 5 seeds (80 runs) against a coarser sign criterion, not the tighter `3·SE` band of the displacement check; the addendum states the resulting SE explicitly (`N=100,000, π=0.2` divided by `√5`) rather than assuming it | `data/prereg/02-token-kat-addendum.md:85,123` |
| Seeds fixed at `0..4` (5 replicates) across every simulated family (displacement, exponent, occupancy, fusion, quotas) | One seed convention across all five pre-registered families lets `tests/test_doc_numbers.py` check seed-level sign counts (e.g. "40 of 40 seed-level signs") without re-deriving the RNG contract per family | `docs/THEORY.md:244,252,319,348,424`; convention declared once in `data/prereg/01-displacement-replication.md:80` |
| Pre-registered test statistic is the sign of the predicted vs. observed `ΔAUC`, with a `|ΔAUC| ≥ max(0.005, 3·SE)` "tested" gate that can also come back "not tested" | Prevents the two failure modes of an SE-blind gate: claiming a sign match on noise (SE too large relative to the effect) and silently dropping a cell that never crossed the pre-registered floor — both are visible in the sealed data (e.g. `B->BC, d_C=0.05` has `testado: false` because `|delta_analitico|=0.0035 < 0.005`) | `data/prereg/01-displacement-replication.md:108,141-142`; observed case in `output/figures/fig3_values.json` (`painel_a.painel_a.pontos` entry with `"testado": false`) |
| Exponent/occupancy/fusion/quotas addenda each run at `K = 2048` tokens with margin `z ≥ 4`, `N = 100,000`, 5 seeds, `k ∈ {14, 55}` | Reuses one budget/cost pair across four follow-up families so a cell's saturation margin is comparable across families instead of re-justifying `K` and `k` four times | `docs/THEORY.md:319,348,423` |
| `K = 2048` itself is not a free parameter — it is read from the case study's stated context window | Keeps the simulated grid inside the scope the paper claims (nuFormer's transaction model), instead of an arbitrary round number chosen for simulation convenience | `docs/THEORY.md:21-24` |
| Network/latency estimates (all-reduce per link, synchronous-path compute latency) computed from the case study's published configuration, not measured on real hardware | The repository states explicitly this is a counterfactual/order-of-magnitude reading of the published numbers, not a benchmark, and reports both the assumption and the resulting bound (e.g. "≈5 ms minimum compute latency... at 100% of dense BF16 peak, so a lower bound") | `README.md:164,166,171-175` |
| Estimates ledger (`configs/estimates_inputs.json`) kept separate from the claims ledger, and the claims ledger kept outside the provenance chain | Lets the inputs to every order-of-magnitude estimate be inspected and regenerated independently of the hash-sealed simulation chain, so an estimate can be corrected without breaking the chain's integrity guarantee | `README.md:63-65,354-356` |
| Provenance chain: Merkle tree per stage (`environment -> code -> prereg -> data -> scores -> figures`, RFC 6962 domain separation, stages folded in order) | Makes the ordering of the seven stages itself part of what a single hash proves — a run cannot be replayed with a later-stage file smuggled into an earlier stage without changing the root | `REPRODUCIBILITY.md:144-151` |
| Chain verification recomputes from disk (`manifest.json`, `sha256sums.txt`, `CHAIN.jsonl`) rather than trusting a stored verdict | The exit code is the number of mismatches, so "chain verified" is a re-derived fact each time CI or a reader runs it, not a claim carried over from the sealing run | `REPRODUCIBILITY.md:151-166,105` |
| `code/provenance_chain.py selftest` (known-answer + tamper-detection tests) ships alongside the chain tool | A hash-chain library with no self-test is unfalsifiable — the selftest is what lets a reader trust the tool computed the chain correctly, not just that it ran | `REPRODUCIBILITY.md:172` |
| Chain explicitly documents what it does *not* prove (only integrity/order of sealed bytes, not correctness of the science) | Prevents the chain from being read as validating the theory — that job belongs to the sign tests in `docs/THEORY.md`, not to the hash chain | `REPRODUCIBILITY.md:175-179` |
